# UNO Social Club

一个固定全屏、适配桌面与手机的 3D UNO Demo：深绿牌桌、精细卡面、悬浮倾斜、飞牌、粒子与胜利彩纸。**当前版本是可直接部署到 GitHub Pages 的静态人机游戏，无需后端、数据库或云服务配置。在线匹配和好友联机暂未开放。**

试玩入口：[tanghme0w.github.io/uno-social-club](https://tanghme0w.github.io/uno-social-club/)。

## 当前可玩内容

- 游戏画面占满视口，手牌固定在底部；村规、档案、难度和设置收在菜单内。
- 四人 AI 练习，提供休闲、标准、高手三档难度。
- 9 项自定义村规，以及经典、休闲、混战 3 个预设。
- 真实 3D 牌桌、带反光的卡面、扇形手牌、悬浮倾斜、飞牌和胜利彩纸。
- 手机触摸选牌、手牌滚动、横竖屏响应布局；音效、震动（浏览器支持时）、减少动态效果设置。
- 无密码的本地玩家档案：可创建和切换玩家，查看当前档案的近期战绩。
- 本机最多保存 8 个档案；所有档案合计只保留最近 50 局且不超过 30 天的已完成对局。
- 游戏偏好、档案和战绩保存在当前浏览器。清理站点数据或换设备后不会自动恢复。

本次发布不要求注册登录。本地档案不是跨设备通用账号，昵称只需在本机档案中不重复；也不会用 AI 冒充在线真人对手。托管实时联机留作后续工作。

## 本地试玩

建议使用 **Node.js 24 LTS**。

```sh
npm ci
# 中国大陆网络可用：npm ci --registry=https://mirrors.cloud.tencent.com/npm/
timeout 24h npm run dev
```

打开 `http://localhost:10888` 即可玩。手机可以访问电脑的局域网地址，例如 `http://192.168.1.10:10888`；电脑需要允许设备访问该端口。当前游戏不需要执行 `npm run server`。

## 部署到 GitHub Pages

1. 将源码推送到自己的 GitHub 仓库，默认分支设为 `main`。
2. 在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 推送到 `main`，或手动运行 **Deploy UNO to GitHub Pages** 工作流。
4. 工作流安装依赖、执行测试、检查 TypeScript 并构建，再将 `dist/` 部署到 Pages。
5. 在工作流或 Pages 设置中取得 `https://用户名.github.io/仓库名/` 地址，桌面和手机均可打开。

**无需填写任何环境变量、API Key、数据库连接或服务器地址。** `vite.config.ts` 使用相对资源路径 `base: './'`，适配仓库子路径。当前应用没有需要服务器回退的深层路由。

工作流依照 [Vite 静态部署](https://vite.dev/guide/static-deploy.html#github-pages) 和 [GitHub Pages 自定义工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) 配置。实际远端仓库和 Pages 发布结果以 GitHub 返回的状态及 URL 为准。

## 玩法与村规

点击卡牌选中，再点击一次或按「出牌」。剩两张时先按 UNO，再出到剩一张；漏喊按本局设置立即罚摸。万能牌出牌时选择颜色，7 换手时选择玩家。

菜单 →「自定义村规」设置下一局规则，点击「按这个规则开一局」生效。可设置起始手牌数、罚牌叠加、摸牌方式、摸后必出、7/0、同牌抢出、严格 +4、漏喊处罚和功能牌收尾。准确语义见 [规则说明](docs/RULES.md)；本项目没有 +4 质疑流程。

## 本地档案与遗忘窗口

打开右上角菜单，选择「玩家与战绩」，输入 2–24 个字符的昵称创建本地玩家；已有档案可以直接选择入座，不需要密码。登录状态和资料只属于当前浏览器，不提供跨设备身份验证或同步。

已完成的人机对局会记录到当时选择的档案下，包括胜负、回合数、结束时间、玩家剩余牌数和本局村规。重复处理同一结果不会重复累计。档案页面显示当前玩家的近期历史；战绩统计来自当前保留的记录，会随着窗口清理而变化，并非永久累计排行榜。

存储采用两个上限中更严格的那个：所有档案合计最多 **50 局**，且只保留 **30 天**内的对局，读写时清理。最多 **8 个档案**；创建更多时淘汰最近最少使用的非当前档案及其记录。这样无需后台清理任务，也不会持续积累完整牌局日志。

## 构建和检查

```sh
npm test
npm run build
timeout 24h npm run preview
```

`npm run build` 先运行 TypeScript 检查，再构建可静态托管的 `dist/`。当前 Node 测试集包含 48 项：规则、村规、牌张守恒、完整 AI 对局和历史联机共 37 项，以及本地档案和遗忘窗口 11 项；实际通过结果以本次运行记录为准。仓库内保留的旧联机测试不代表本次静态发布开放在线服务。

浏览器验收使用 Playwright，覆盖桌面选牌与村规、手机横竖屏与设置、本地档案刷新后保留及联机延期提示。先启动开发前端：

```sh
npx playwright install chromium
npm run test:browser
```

当次实际通过数量与浏览器检查结果以运行记录为准。测试输出、截图、打包产物和本地记录位于忽略提交的 `runs/`。

低性能设备可开启「减少动态效果」；WebGL 不可用时牌桌保留 CSS 视觉表现。
